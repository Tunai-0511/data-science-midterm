# 資料科學期中報告：網路爬蟲 17 題

每一題是一個資料夾，裡面有 **程式 `main.py`** 和 **執行後的輸出檔**（CSV／HTML）。
程式可以單獨執行，重新執行會**直接覆蓋**同一個輸出檔，不會另外產生新檔案。
每支程式最上面都有一段說明：題目要求、做法、輸出檔、執行指令。

> 本 repo 整合了組員兩個版本（[Einosensokami/Data_Science_Einosensokami](https://github.com/Einosensokami/Data_Science_Einosensokami)、[Tunai-0511/data-science-midterm](https://github.com/Tunai-0511/data-science-midterm) 舊版），
> 並依 2026-10-14 各網站的實際版面重新撰寫、逐題實測。

## 一、安裝環境（只要做一次）

需要：**Python 3.10 以上**、**Google Chrome**。
ChromeDriver 不用自己下載，Selenium 會自動下載與 Chrome 版本相符的驅動程式。

```bash
pip install -r requirements.txt
```

如果想裝在虛擬環境裡（可選）：

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

> macOS 若 `python` 指令不存在，請改用 `python3`。

## 二、執行方式

在本資料夾（`requirements.txt` 所在位置）開終端機：

```bash
python run.py 5
```

一次執行一題：`run.py` 後面接題號，上面就是執行第 5 題，等同 `python 第05題_台北票房排行榜/main.py`。
只打 `python run.py` 會先列出所有題目，再輸入題號。

用到 Selenium 的題目會自動打開 Chrome 視窗操作，完成後自動關閉，可以直接看到程式操作的過程。

### 第 1 題：開眼電影網本週新片
- **題目**：抓 <http://www.atmovies.com.tw/movie/new/> 的本週新片，包括標題、內容、片長、網址。
- **做法**：requests 下載頁面 → BeautifulSoup 找每個 `<article class="filmList">`，取標題、簡介、片長（正規表示式取「片長：117分」）、網址。
- **延伸：點進每部電影的內頁**：題目只要求列表頁的四個欄位；我們再打開每部電影的內頁，多抓上映日期、上映廳數、評分、評分人數、導演、演員、影片年份、出品國、語言、發行商。內頁的演職員區塊 `<li>` 沒有正確關閉、層層巢狀，所以依節點出現的順序走過去：遇到 `<b>導演：</b>` 這類標籤就換欄位，後面的人名或文字都歸到這個欄位。每部片之間停 1 秒，避免連續請求造成網站負擔。
- **延伸欄位的意義**：上映廳數代表片商排了多少廳、對票房的期待（院線規模）；評分要搭配評分人數看，人數很少時參考價值低，0 人評分時評分留白、不當成 0 分；出品國、語言看得出本週新片來自哪些國家；影片年份比上映日期早很多的是重新上映的舊片（例如《進擊的鼓手》）。
- **輸出**：`new_movies.csv`（題目要求的標題、內容、片長、網址）、`new_movies_detail.csv`（延伸：四個欄位＋內頁 10 個欄位）
- **執行**：`python 第01題_本週新片/main.py`

### 第 2 題：臺灣銀行牌告匯率
- **題目**：抓 <https://rate.bot.com.tw/xrt?Lang=zh-TW> 最新掛牌資料，存入 `bank.csv`。
- **做法**：臺銀網站現在有「瀏覽器驗證」，requests 只會拿到驗證頁，所以用 Selenium 開 Chrome 載入，再用 BeautifulSoup 解析匯率表。每個儲存格都有 `data-table` 屬性（例如「本行現金買入」），依屬性取值，避免題目「參考範例」那種欄位錯位、重複的問題。
  匯率表的完整內容是幣別、現金匯率、即期匯率、遠期匯率、歷史匯率。遠期、歷史匯率在表上只是「查詢」連結（另外的網頁），所以存它們的網址，再加上表格上方的掛牌時間。網頁另外藏了一組列印用的欄位，標題寫「歷史匯率」，但數字和現金、即期匯率完全一樣，不是另外的資料，所以不重複存。
- **延伸：買賣價差**：銀行賣出價（你跟銀行買外幣）一定比買入價（你賣回給銀行）高。價差（%）＝（賣出 − 買入）÷ 賣出 × 100，代表用台幣買進外幣再立刻賣回會損失幾 %。例如美金現金約 2%、即期不到 0.5%；印尼幣、越南盾這類只有現金匯率的幣別，價差可以到 30% 左右，所以出國換這類貨幣時，在台灣換現金最不划算。
- **輸出**：`bank.csv`（幣別、現金匯率-本行買入／賣出、即期匯率-本行買入／賣出、遠期匯率與歷史匯率的查詢網址、掛牌時間）、`bank_detail.csv`（延伸：現金與即期的價差、價差 %）
- **執行**：`python 第02題_台銀牌價/main.py`

### 第 3 題：健保門診及住院就診人次統計－腸病毒
- **題目**：從政府資料開放平臺抓取這份資料，存成 `NHI_EnteroviralInfection.csv`。課堂補充：不能自己用滑鼠點網頁找到資料就說抓到了，要用程式模擬。
- **做法**：照題目附圖的步驟，由 Selenium 模擬操作：開啟 data.gov.tw → 首頁搜尋框輸入「腸病毒」並按搜尋 → 在結果中點「健保門診及住院就診人次統計-腸病毒」（開在新分頁，程式會切換過去）→ 讀出資料集頁面「CSV」按鈕的下載網址 → 用 requests 下載並存檔。
  （用完整名稱搜尋時，平臺會把同系列的其他疾病排在前面，所以用「腸病毒」搜尋，目標資料集就在第一頁。）
  為了讓人看清楚每一步，程式操作前會把要點的元素捲到畫面中間，終端機印出「步驟 n」說明，停 2 秒再動作（秒數在程式開頭的 `STEP_PAUSE` 設定，改成 0 就不停）。
  下載網址在疾管署網站，憑證鏈不完整、Python 預設會驗證失敗，所以先用 `truststore` 改用作業系統的憑證庫驗證；還是失敗時才改用不驗證憑證的方式下載，並印出提示。
- **延伸：年齡別與縣市地圖**：用 pandas 把整份資料（2016 年到最新一週）加總，畫成一張圖：
  - 左邊是各年齡層的就診人次長條圖：0～12 歲占九成以上，其中又以 3～6 歲（學齡前）最多（例：2026-10 執行時約占 44%），看得出腸病毒主要是幼兒園、托嬰中心的防疫重點。
  - 右邊是台灣地圖，各縣市的累計就診人次分 5 級上色（5 萬以下、5～10 萬、10～20 萬、20～40 萬、40 萬以上，由黃到深紅），旁邊列出 22 個縣市的排名與人次。人口多的新北市、台中市最多。澎湖、金門、連江三個離島放大畫在左下角標「離島」的框裡；金門的框只畫大、小金門，遠在東北方的烏坵不畫。
  - 注意是「就診人次」不是「人數」，同一個人看兩次診會算兩次。
  - 縣市邊界 `taiwan_counties.geojson` 來自內政部國土測繪中心「直轄市、縣市界線(TWD97經緯度)」（<https://data.gov.tw/dataset/7442>，政府資料開放授權），經 [taiwan-atlas](https://github.com/dkaoster/taiwan-atlas)（MIT 授權）簡化成 TopoJSON，我們再轉成 GeoJSON。程式用內建的 `json` 讀進來、用 matplotlib 畫多邊形，不需要另外安裝地圖套件。
- **輸出**：`NHI_EnteroviralInfection.csv`（約 19 萬筆、8 MB）、`enterovirus_charts.png`（延伸：年齡別長條圖＋縣市地圖）
- **執行**：`python 第03題_腸病毒資料/main.py`

### 第 4 題：博客來「演算法」書籍
- **題目**：`https://search.books.com.tw/search/query/key/{0}/cat/all`，`{0}` = 演算法；存入 `booklist.csv`，欄位 書名、網址、作者、書價。
- **做法**：博客來有 Cloudflare 防護，requests 會被擋（403），改用 Selenium 開 Chrome 載入題目網址，再用 BeautifulSoup 解析每本書：書名、作者、書價（優惠後售價，元）、網址（換成正式商品頁 `https://www.books.com.tw/products/商品編號`）。
  解析完逐筆印出每本書，寫入 `booklist.csv`。
- **範圍**：題目網址就是搜尋結果第 1 頁（60 本；例：2026-10 時網站顯示共 673 筆、12 頁）。換到第 2 頁時博客來會跳出「Verify you are human」真人驗證；2026-10 實測放慢翻頁、由真人在程式開的瀏覽器裡勾選，都無法通過。程式不繞過驗證，所以只抓題目指定的網址。
- **延伸：書價分布與離群值**：
  - 價格轉數字，檢查重複網址與缺漏；統計與圖表標題均由資料計算。
  - 程式印出最低價、Q1、中位數、Q3、最高價、平均數、IQR 與上側離群判定界線（Q3 + 1.5 × IQR），並列出超過界線的書；數字每次執行都會隨網站售價變動。
  - 例：2026-10-20 執行時 60 本都有價格，中位數 458 元，300～550 元的書約占七成；《演算法導論 第四版》1,422 元超過界線。
  - 左圖自動分箱呈現價格分布；右圖為箱型圖並標示上側界線。IQR 是 Q3 − Q1 的差值，Q1～Q3 是中間 50% 的價格區間。
  - 分析僅限搜尋第一頁的優惠售價，未蒐集裝訂、頁數或成本，不能據此解釋價格成因。
- **輸出**：`booklist.csv`（60 本）、`booklist_detail.csv`（延伸：數值化價格）、`book_price_charts.png`（延伸：圖表）
- **執行**：`python 第04題_博客來書籍/main.py`（加 `--analyze-only` 可直接使用既有 CSV 分析繪圖）

### 第 5 題：開眼台北週末票房排行榜
- **題目**：按「票房排行榜」→ 列出台北排行榜的排名、片名、票房 → 按 more → 20 筆存入 `Taipei_movies.csv`（排名、片名、本週票房、累計票房）。課堂補充：要模擬滑鼠移動及點選。
- **做法**：Selenium `ActionChains`：滑鼠移到「電影」選單展開 → 點「票房排行榜」→ 印出台北前 5 名 → 點台北排行榜的「more」→ 讀出 20 筆（每部電影在網頁上占兩列，第二列才是票房數字）。
- **網站干擾的處理**：點連結時偶爾會跳出 Google 全版廣告（網址出現 `#google_vignette`），程式會像真人一樣按「關閉」再繼續；票房網站偶爾連線逾時，會自動重新整理再試。
- **穩定性**：滑鼠移到「電影」選單時，下拉選單偶爾沒展開，程式會把滑鼠移開再移回來重試；點「票房排行榜」或「more」後 20 秒沒換頁，就重新找到連結再點一次（都是最多 3 次）。
- **延伸：票房分布與集中程度**：
  - 去除 `$` 與逗號，轉數值後依本週票房排序；無效本週票房揭露並排除於占比。先計算精確占比，顯示時才四捨五入。
  - 程式印出榜內總票房，以及前 3、5、10 名和前 20% 片數占榜內票房的比例；前 20% 片數的占比不一定到八成，所以不直接稱為「二八法則」。
  - 例：2026-10-20 的榜單，前 3 名約占三成多、前 10 名接近八成，票房集中在少數幾部片。
  - 左圖為前 10 名票房橫條圖，右圖為榜內累積占比曲線，80% 只是參考線。
  - 分母僅為本次榜單總票房，不能當成全市場占比；未蒐集排片、行銷等資料，不能推論集中程度的成因。
- **輸出**：`Taipei_movies.csv`（金額單位：萬新台幣）、`Taipei_movies_detail.csv`（延伸：數值化與佔比）、`boxoffice_charts.png`（延伸：圖表）
- **執行**：`python 第05題_台北票房排行榜/main.py`（加 `--analyze-only` 可直接使用既有 CSV 分析繪圖）

### 第 6 題：NBA 球隊球員（Basketball Reference）
- **題目**：`https://www.basketball-reference.com/teams/{0}/2024.html`，抓 CLE、HOU、GSW 三隊，欄位 球隊、背號、姓名、位置、體重、生日、經驗、大學，存入 `players.csv`。
- **做法**：題目網址就是各隊的「Roster & Stats」頁。requests 下載三隊頁面 → BeautifulSoup 找 `table#roster`（Roster 名單），依每格的 `data-stat` 屬性取值。三隊之間間隔 3 秒，避免請求太快被封鎖。
- **資料說明**：體重單位為磅；經驗 `R` 代表新秀；沒讀大學的球員「大學」為空白。

  2. 移除重複的飯店（同一間出現在不同頁，用飯店 ID 判斷，只留第一次）。

  程式會印出每一步移除幾筆，每次執行都不同（例：2026-10-20 執行時原始 539 筆 → 移除沒有價格 45 筆、重複 11 筆 → 處理後 483 筆）。
- **延伸：平台地區房價與價格評分關係**：
  - 保留 Agoda 的原始地區分類，統稱「平台地區」，因為資料同時含行政區、商圈與景點（例如西屯區／逢甲、和平區／谷關），不能當作一致的行政區比較。
  - 程式印出各平台地區的樣本數、中位數、平均、最低與最高價；地區價格統計使用全部有價格的住宿，包含沒有評分的。例：2026-10-20 執行時，至少 4 筆的地區中中位數最高的是和平區、東勢區、谷關這些山區景點，市區的中區、北區約 1,000 元。
  - 箱型圖按中位數排序，標示樣本數；各少於 4 筆的地區合併為其他。兩圖價格軸使用對數刻度，保留高價資料，未裁切在 12,000 元；最高價可到十幾萬元，須留意不同住宿類型與房型的可比性。
  - 程式印出價格與評分的 Pearson r、高價組（價格 >= Q3）的筆數與平均評分、全體平均評分，以及高價組裡低於 8.5 分的筆數。例：2026-10-20 執行時 r 約 0.18，只有很弱的正相關，高價組平均評分只比全體高一點。
  - 程式也算出「價格不高於中位數、評分不低於中位數」的住宿有幾筆，找出相對划算的選擇。這些是描述統計，未做顯著性檢定，不能推論品牌、硬體、服務造成價格或評分差異；價格為每晚未稅報價，查詢日期、房型與評論數也影響比較。
- **輸出**：`agoda_result.csv`（沒有資料處理）、`agoda_result_processed.csv`（有資料處理）、`agoda_charts.png`（延伸：圖表）。價格為每晚、不含稅及其他費用，會隨查詢日期變動。每頁約 40 秒，全部約 4～5 分鐘。
- **執行**：`python 第16題_Agoda台中飯店/main.py`（加 `--analyze-only` 可直接使用既有 CSV 分析繪圖）

### 第 17 題：GitHub 自動登入
- **題目**：用 Selenium 及 WebDriver 自動登入帳號，抓取附圖 1 號視窗與 2 號視窗的頁面資料。課堂補充：難點在登入表單裡隱藏的 key 值。
- **做法**：
  1. 執行時在終端機輸入 GitHub 帳號、密碼（帳號照常顯示，密碼每個字顯示成「•」；不會存檔）；也可事先設定環境變數 `GITHUB_USERNAME`、`GITHUB_PASSWORD`。
  2. Selenium 開啟登入頁，自動填入帳密並按 Sign in。登入表單裡有 `authenticity_token` 等隱藏欄位（就是「隱藏的 key 值」，每次開頁都不同）：用 requests 登入要自己先從網頁抓出來、跟帳密一起送出；用 Selenium 是在瀏覽器裡按登入，瀏覽器會自動送出。程式會找出這些隱藏欄位，印出欄位名稱和 `authenticity_token` 的開頭幾個字元。
  3. 送出帳密後 GitHub 可能還要再驗證一次，請在 Chrome 視窗中完成，程式最多等 5 分鐘（程式一開始會先提醒）：
     - 有開二階段驗證（2FA）：輸入驗證 App／簡訊的 6 位數驗證碼，或用通行金鑰確認；
     - 沒開 2FA：程式每次開的都是全新的 Chrome，GitHub 會當成新裝置，通常會寄 Email 驗證碼，到信箱查看後輸入即可。
  4. 登入後抓首頁：**1 號視窗＝左欄**（新帳號顯示「Create your first project」，已有專案的帳號顯示「Top repositories」）；**2 號視窗＝中間主欄**（附圖當時是「Updates to your homepage feed」提示卡，改版後是首頁動態面板）。依區塊位置抓取，新舊版首頁都適用。
- **輸出**：兩個視窗分開存，各有一份 CSV 和一張截圖。CSV 有「內容」「連結」兩欄：一行文字一列，那行文字是連結的話（例如 Top repositories 的 repo 名稱），用 `get_attribute("href")` 存完整網址 `https://github.com/Tunai-0511/…`，點了就能打開；不是連結就空白。檔名：1 號視窗（左欄）`github_window1_left.csv`、`github_window1_left.png`；2 號視窗（中間主欄）`github_window2_center.csv`、`github_window2_center.png`。截圖只截那個區塊，比視窗高也會截完整。首頁的區塊是陸續載入的（中間主欄一開始只有轉圈圈，左欄的 Top repositories 也比 Home、Feed 晚出現），程式會兩個視窗一起等：都有文字、沒有轉圈圈或灰色骨架（載入中），而且連續 3 秒沒有再變，才讀取和截圖，最多等 45 秒。附上的輸出是組員用自己帳號實際執行的結果；換別人執行會抓到他自己帳號的首頁。
- **執行**：`python 第17題_GitHub登入首頁/main.py`
