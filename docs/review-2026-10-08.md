# 2026-10-08 程式複查

本次只做離線複查與修正，沒有重新連線抓取網站。複查環境的網路政策封鎖了所有來源網站，因此無法在此重跑實測；各題網站狀態仍以 [2026-09-10 實測摘要](status-2026-09-10.md) 為準。

## 發現並修正的問題

| 範圍 | 問題 | 修正 |
| --- | --- | --- |
| 第 16 題 | `parse_results` 會檢查「入住日不可早於今天」。2026-10-02 起，4 項使用固定日期 2026-10-01 的解析測試失敗；已保存的結果頁過了入住日也無法重新解析。 | 解析只檢查日期格式與先後；「不可早於今天」只在實際送出搜尋前檢查。 |
| 命令列參數 | 過去或顛倒的日期、0 位成人要到第 16 題執行時才失敗，`status.json` 只顯示 `ValueError：執行未完成`。 | `run_cli` 與 `run_all.py` 在建立結果目錄、開啟瀏覽器前檢查參數，直接顯示原因。 |
| 第 9、12、15 題 | 驗證頁判斷只看文字關鍵字；新聞標題含「異常流量」或搜尋摘要提到 CAPTCHA 時，正常頁面會被誤判為來源阻擋。 | `/sorry/` 網址仍直接判定為驗證頁；文字關鍵字只在頁面沒有結果區（`#search`、`main`）時才算。 |
| 第 5 題 | 「逾時就重新整理一次」的函式寫好了卻沒有被呼叫；來源超過 20 名時，說明會誤寫成「網站當下只提供 N 名」。 | 等待台北 more 連結時改用此函式，仍失敗時區分 Chrome 連線錯誤（阻擋）與版面改變（部分完成）；依排名保存前 20 名。 |
| 第 11 題 | 換頁重繪表格時，若剛好讀到失效的儲存格，整題會變成錯誤。 | 等待換頁時忽略 `StaleElementReferenceException` 並重新查找。 |
| 測試 | 3 處 `read_text()` 沒有指定編碼，在繁體中文 Windows（cp950）會出現 `UnicodeDecodeError`；2 個測試檔要靠其他測試先加入專案路徑才能匯入題目程式。 | 明確使用 UTF-8；每個測試檔自行加入專案根目錄，可單獨執行。 |
